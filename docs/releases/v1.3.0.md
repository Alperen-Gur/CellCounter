# CellCounter v1.3.0 for macOS

This release gives every image its own pixel scale, lets you decide how much of your Mac the
models may use, moves Cellpose-SAM to Cellpose 4.2.1.1 with a fixed, tested set of libraries,
and makes the expected cell size visible wherever it matters.

Requires **macOS 15 or later on Apple silicon**. Ad-hoc signed and not notarized. Intel Macs are
no longer supported.

## Pixel scale for each image

- **Each image has its own scale.** When a file records its scale (TIFF or JPEG resolution,
  OME-XML, ImageJ or a microscope format), that image is measured at it, so one folder can mix
  objectives.
- **No built-in scale.** The preset microscope scales and the hidden default of 2.6 px/µm are
  gone. **Set up analysis** lists the scales it found and the images that have none; an analysis
  starts only when every image has a scale. Set one by drawing on the scale bar, typing px/µm or
  choosing your own saved preset (for example "Nikon Ts2 · 10×").
- **A file's scale is never replaced silently.** Overriding it is an explicit choice that shows
  both values and what changes, and is recorded as a manual override.
- **Changing the scale after analysis** offers **Re-run segmentation** (recommended) or **Only
  rescale sizes**, because Cellpose models use the scale to decide how large a cell is. Rescaled
  results say which scale they were segmented at.
- The scale and its source are shown above each image, in the toolbar and in the batch header,
  and every export records them.
- Setup warns when file names such as `10x` and `20x` do not match the scales found.

See [Pixel scale](https://github.com/Alperen-Gur/Cellographer/blob/v1.3.0/docs/INSTALL.md#pixel-scale-pxµm).

## Model resource use

- New **Settings → General → Performance**: **Light**, **Balanced** (default), **Maximum** or
  **Custom** CPU cores and memory.
- **Light** keeps your Mac fully usable while a model runs; analysis can be much slower.
- Switch at any time, including during an analysis: from the **Resource use** menu next to
  **Pause** and **Cancel**, from **CellCounting → Model Resource Use** in the menu bar, or in
  **Set up analysis**. Priority, CPU cores and a higher memory cap apply to the running model at
  once, without reloading it.
- Covers analyses, Workbench model runs and training.

See [Model resource use](https://github.com/Alperen-Gur/Cellographer/blob/v1.3.0/docs/INSTALL.md#model-resource-use).

## Cellpose-SAM on Cellpose 4.2.1.1

- Cellpose-SAM is installed with Cellpose 4.2.1.1 and a fixed set of tested libraries (PyTorch
  2.12, torchvision 0.27, OpenCV 4.13, NumPy 2), so every new installation runs the same code.
- An existing installation shows **Update Cellpose-SAM to 4.2.1.1** in **Models**. Nothing changes
  until you click it. Results can differ slightly from runs made with the older version.
- **Cellpose-SAM v2** now runs the revised model, with its own one-time download of about 1.2 GB.
  With older Cellpose versions, v2 and Cellpose-DINO silently ran the original Cellpose-SAM; such
  results are marked in their exports.
- **Cellpose-DINO** is listed as unavailable: it needs the `dinov3` package, which CellCounter does
  not install. A model name the installed Cellpose does not know is now refused instead of
  replaced.
- Every result records the Cellpose, PyTorch, NumPy and OpenCV versions, the device and the
  weights file it used, in its CSV header, `provenance.json` and report.

## Expected cell size

- **Set up analysis** has an **Expected cell size** section with the value in pixels at the
  current scale, warnings when it is outside the range the model handles well, and **Measure on
  image** to set it by dragging across a cell.
- Choosing a size no longer changes Omnipose or classical segmentation until you enter one.
- Results, reports and exports show the expected size each run used. Onboarding explains it.

## Faster analysis, same results

- Cellpose-SAM's mask quality check, pixel tracking and an unused flow image are computed with
  less work. The masks are designed to stay identical bit for bit; the faster code switches itself
  off unless Cellpose is exactly 4.2.1.1 and passes a self-check.
- Cell outlines are simplified for all cells of an image at once, with the same outlines as before.

## Model downloads

- Interrupted weight downloads resume where they stopped, are checked against the size the server
  reports and use verified HTTPS only. A partial download is never mistaken for usable weights.
- Damaged weights are set aside and downloaded once more automatically. Leftover partial files are
  cleaned up, and only CellCounter's own.

## Fixes

- Area assays (confluence, scratch wound, spheroid) use the picked file's own scale and refuse to
  run without one, instead of measuring at 1 px/µm.
- Training explains how to repair a damaged base model.
- Workbench Cellpose runs no longer fail on read-only float images.
- Custom StarDist models and ensembles record correctly how they used the expected cell size.

## Update

Download `CellCounter-v1.3.0.zip` and its `.sha256` file. Quit the old app and replace
**CellCounting.app** in Applications. The first time this version opens a library, it saves a
verified copy of the library's database in its `Backups/` folder before upgrading it. Batches
analysed with an earlier version keep their numbers. To use Cellpose 4.2.1.1, click **Update
Cellpose-SAM to 4.2.1.1** in **Models**. Read
[Upgrade from an earlier version](https://github.com/Alperen-Gur/Cellographer/blob/v1.3.0/docs/INSTALL.md#upgrade-from-an-earlier-version)
before going back to an older version.
